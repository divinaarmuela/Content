1. Purpose and Context
What is being built: A client-facing and team-facing dashboard for MD Media that brings asset links, review stages, comments, approvals, scheduling status and published links into one place.
Why it matters: The current process uses multiple disconnected tools such as Dropbox, Google Drive, Asana, WhatsApp/manual follow-up and scheduling tools. This causes gaps in visibility for clients and creates extra back-and-forth for the internal team.
Design Principle
The Account Manager is the central gatekeeper. Editors should not directly manage client communication, and schedulers should only be involved once content has been approved for scheduling.

2. Current Pain Points to Solve
Too many disconnected tools: Assets and updates are split across Dropbox, Google Drive, Asana, WhatsApp and scheduling tools.
No live client visibility: Clients often need to ask what has been created, reviewed, scheduled or posted.
Manual link forwarding: The team manually passes Drive links between editor, account manager and scheduler.
No clear review trail: Changes can happen verbally or in scattered comments, making accountability difficult.
Scheduler receives content too early: Schedulers should only receive items after client/AM approval, not during internal revision loops.
Client comments need routing: Client feedback should come to the Account Manager first, then be translated into internal editor tasks.
Future product potential: This MVP should be structured in a reusable way so the same workflow can later be productised for other agencies/teams.

6. Team Dashboard Requirements
Kanban or funnel board: Columns should mirror the production statuses: Draft Uploaded, Internal Review, Revision Required, Client Review, Approved for Scheduling, Scheduled, Published.
Client/month filters: Filter by client, month, campaign/shoot, asset type, owner, due date and status.
Batch + item view: A shoot may produce 16-20 videos. The dashboard should allow one batch record plus item-level records for individual videos/carousels.
Version history: Every revised upload should be saved as a new version rather than replacing the original without trace.
Link centre: Each content item should store internal Dropbox link, Drive review link and final published link separately.
Comment threads: Comments must be anchored to an asset/item, optionally timestamped for video edits, and resolvable.
Quick handoff buttons: Submit for internal review, Request revision, Send to client, Approve for scheduling, Mark scheduled, Mark published.
Activity log: Every status change, comment, upload and approval must be timestamped with the user who performed it.

7. Client Dashboard Requirements
Simple monthly view: Client sees each month, committed deliverables and actual progress. Example: 10 reels + 4 carousels committed; 4 reels completed; 6 reels pending; 1 carousel completed; 3 pending.
Calendar view: Client can see which post was/will be published on which date and platform.
Review section: Client can see items that need their review and leave comments or approval.
Published links: Client can click live Instagram, Facebook, TikTok, LinkedIn or other platform links once published.
Request update/comment: If dashboard looks empty or delayed, client can leave a comment asking for an update rather than chasing on WhatsApp.
No internal noise: Client should not see internal editor notes, revision arguments, Dropbox archive links or other client data.

11. Storage and Link Handling Rules
Dropbox link: Internal archive/master file location. Visible to Admin, Account Manager and Editor as required. Not client-facing by default.
Google Drive link: Universal team/client review link. Used for AM review, client review and scheduler handoff.
Published link: Final live platform URL added after publishing. Visible on client dashboard.
Version control: A revised video should create a new Asset Version record. The latest approved version becomes the scheduler-facing version.
Missing link validation: Editor cannot submit for internal review unless the minimum required links are present.
Client-safe view: Client view should show only approved/review-ready Drive/preview links and live published links.

Implementation Advice for Developer
Avoid hard-coding MD Media-specific role names or fixed quotas. Use configurable workspaces, role permissions, content types and status pipelines wherever practical. This will make the dashboard easier to evolve into the future product.

14. Acceptance Criteria
An editor can create a batch, add 20 edited videos, attach Dropbox and Drive links, and submit them for internal review.
The assigned Account Manager receives a notification when a batch/item enters Internal Review.
The Account Manager can comment on individual assets and request changes from the editor.
The editor receives only internal revision comments and can mark revisions complete with a new upload/link version.
The Account Manager can send internally approved content to the client for review.
The client can approve or request changes from their dashboard without seeing internal comments.
Client comments notify the Account Manager, not the editor directly.
The Account Manager can turn client comments into internal editor tasks.
The scheduler only receives a notification once content is marked Approved for Scheduling.
The scheduler can add scheduled dates/platforms and final live links after publishing.
The client dashboard updates monthly progress counts and calendar entries automatically when items are scheduled or published.
Admins can audit status changes, comments, approvals and versions.

16. Open Questions for Developer / Team
Should the dashboard upload actual files directly, or should Phase 1 only capture Dropbox/Google Drive links?
Should client approvals happen item-by-item, batch-by-batch, or both?
Should the client receive instant notifications for every review item, or a bundled daily/weekly review digest?
Should AM approval be required after the client approves, or should client approval directly move content to Approved for Scheduling?
How should seasoned clients be handled if client approval is sometimes skipped? Suggested answer: add a Client Approval Required toggle per client/batch.
Should published links be manually pasted by scheduler in MVP or pulled from scheduling/social APIs later?
What is the expected SLA for internal review, client review and scheduling handoff reminders?
17. Final Build Summary
Build the dashboard around one core content lifecycle: Editor upload → Account Manager internal review → revision loop → client review → approval → scheduler handoff → scheduled → published.
The Account Manager must remain the central controller of communication. This protects the client experience, avoids editors being pulled into client conversations, and ensures schedulers only receive work that is genuinely ready to publish.
The client view should be simple and confidence-building: monthly commitments, current progress, calendar, review items, scheduled posts and published links. The client should never need to chase the team just to know where things are at.
